5. New test workflow
Create a multi-step workflow with progress indicators:

Step 1: Select or create subject
- Search by internal subject ID.
- Do not display sensitive data unnecessarily.

Step 2: Select test kit
- Display kit name, manufacturer, version, expiration status, and available drug panels.
- Prevent selection of expired or disabled kits.

Step 3: Capture or upload image
- Use the device camera with Expo Camera.
- Allow gallery upload.
- Show camera permissions.
- Include flash control if supported.
- Include retake and cancel buttons.
- Display a clear instruction to place the strip inside the guide.

Step 4: Image quality assessment
Check and display:
- Blur
- Brightness
- Glare
- Strip position
- Image resolution
- Whether the image is usable

For the first version, implement a deterministic mock quality assessor with clearly separated code so it can later be replaced with an on-device AI model. Never present mock analysis as medical-grade AI.

Step 5: Drug panel result
Display each panel as a card:
- Drug name
- Result: negative, presumptive positive, or inconclusive
- Confidence score
- Optional measured value
- Notes
- Manual override requiring a reason

Never automatically convert a screening result into a confirmed diagnosis.

Step 6: Review
Show:
- Subject ID
- Test kit
- Operator
- Date and time
- Location, only after requesting permission
- Image preview
- Image quality score
- Panel results
- Notes
- Consent status

Require the operator to confirm:
“I understand this is a preliminary screening result.”

Step 7: Save test
- Save the test through a protected backend API.
- Show a success screen with a unique test reference number.
- Generate a shareable report only for authorized roles.
- Allow the user to start another test or return to the dashboard.

BACKEND AND DATABASE

- Organization
- Subject

SECURITY REQUIREMENTS
- Use Argon2 or bcrypt for passwords.
- Use short-lived access tokens and refresh-token rotation.
- Validate all request bodies with Zod or an equivalent library.
- Add authentication middleware.
- Add organization-isolation middleware.
- Add role-based authorization middleware.
- Rate-limit login and sensitive endpoints.
- Use Helmet and secure CORS configuration.
- Never log passwords, tokens, full patient information, or private image URLs.
- Use HTTPS in production.
- Store images in private object storage, not in public URLs.
- Use signed URLs for authorized evidence access.
- Add audit logs for create, read, update, review, export, login, logout, and failed authorization.
- Implement soft deletion for records.
- Add database indexes for organizationId, subjectId, testReference, createdAt, status, and operatorId.
- Add generic error messages for authentication failures.
- Add a privacy notice and consent flow.
- Clearly label all AI or automated results as preliminary screening assistance.

AI AND IMAGE ANALYSIS
For this MVP:
- Create an ImageAnalysisService interface.
- Add a deterministic MockImageAnalysisService for development.
- Return image quality values and panel results from mock data only when the user explicitly selects “Demo mode.”
- Add a placeholder for a future on-device TensorFlow Lite or MediaPipe model.
- Do not send sensitive images to third-party AI services by default.
- Do not use a general-purpose AI chatbot to make a medical or legal decision.
- Always allow “inconclusive” when image quality or analysis is uncertain.
- Keep the final interpretation explainable and reviewable by a human.
